## Project Overview

Climaguate (www.climaguate.com) is an open-source weather forecasting platform for Guatemala. It is a full-stack cloud application with three main components:

- **Frontend**: Blazor WebAssembly (.NET 8) hosted on Azure Static Web Apps
- **Backend**: Python Azure Functions (serverless, timer-triggered)
- **Database**: Azure SQL Server with stored procedures exposed via Data API Builder

## Commands

### Frontend
```bash
cd frontend/Client
dotnet restore
dotnet run                         # Local dev server
dotnet publish -c Release -o bin   # Production build
```

### Backend
```bash
cd backend
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
func start                         # Run Azure Functions locally (requires Azure Functions Core Tools v4)
```

### Full-Stack Local Dev (Azure Static Web Apps CLI)
```bash
swa start                          # Uses swa-cli.config.json (app: frontend/Client, api: backend)
```

### Infrastructure
```bash
cd infrastructure
terraform init && terraform plan && terraform apply
```

## Architecture

### Data Flow
1. **Timer triggers** in `backend/function_app.py` fire on schedule, collecting data from external APIs (OpenWeatherMap, Azure Maps, NASA GOES)
2. Data is persisted to Azure SQL via `pyodbc`; satellite images go to Azure Blob Storage
3. **Data API Builder** auto-generates REST endpoints from SQL stored procedures — there are no hand-written REST handlers
4. **Blazor frontend** calls the Data API Builder REST endpoints directly (base URL configured via `API_Prefix` env var)

### Backend Functions (in `backend/function_app.py`)
- `run_city_batch` — every 20 minutes: collects current weather, air quality, downloads and animates NASA satellite images (APNG)
- `get_hourly_forecast` — daily at 10:00 and 22:00: fetches 24-hour forecasts from Azure Maps

### API Endpoints
All REST endpoints are auto-generated by Data API Builder from stored procedures:
- `GET /rest/GetCities`, `/rest/GetWeather`, `/rest/GetWeatherForecast`, `/rest/GetAirQuality`
- `GET /rest/GetCrops`, `/rest/GetCropsByCity`, `/rest/GetCitiesByCrop`
- Production base URL: `https://climaguate-api.eastus2.cloudapp.azure.com:5001/rest/`

### Frontend Pages (`frontend/Client/Pages/`)
Home, Agriculture, ForecastChart, WeatherHistory, CropCityReport, Alerts, ApiDocs, About. Charts use Chart.js loaded via CDN.

### Database Schema
- `weather` schema: `WeatherData`, `WeatherForecast`, `AirQuality`, `cities`
- `agriculture` schema: `Crops`, `CityCrops` (suitability scores)
- All SQL objects are in `database/*.sql`

## Configuration & Secrets

**Backend requires** (via Azure Key Vault in prod; `local.settings.json` for local dev):
- `connstr` — Azure SQL connection string
- `apikey` — OpenWeatherMap API key
- `azuremapskey` — Azure Maps subscription key

**Frontend** reads `API_Prefix` environment variable to set the backend endpoint.

Azure Functions authenticate to Azure services using **Managed Identity** — no credentials in code.

## CI/CD

Three GitHub Actions workflows under `.github/workflows/`:
- `azure-static-web-apps-*.yml` — deploys frontend on changes to `frontend/Client/**`
- `main_weathercrawler.yml` — deploys backend on changes to `backend/**`
- `sql-workflow.yml` — deploys database changes

## Key Non-Obvious Details

- **No custom REST layer**: all API endpoints come from Data API Builder reading stored procedures directly.
- **Retry logic**: `get_cities_from_api()` retries 3 times with 30-second delays; host.json adds a fixed-delay retry on top.
- **Satellite images**: NASA GOES infrared images are downloaded, watermarked with a weather icon, and assembled into APNG animations stored in Azure Blob Storage per city.
- **Timestamps**: all stored times are converted from UTC to Central America Standard Time (UTC-6) before insertion.
- **No test suite**: there are no automated tests in this repository.
